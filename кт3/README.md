# Служба сокращения URL

Учебный проект на Clojure: HTTP-сервер, терминальный клиент и SQLite.

## Быстрый запуск готового JAR

Требуется Java 17 или новее. Распакуйте архив и откройте терминал в папке `url-shortener`.

Запустите сервер:

```sh
java -jar target/url-shortener-0.1.0-standalone.jar 8080
```

В отдельном терминале из той же папки запустите клиент:

```sh
java -jar target/url-shortener-0.1.0-standalone.jar
```

Готовый JAR содержит зависимости: для его запуска Clojure и Leiningen устанавливать не требуется.

Сервер создаёт `url-shortener.db` в текущей папке. Ссылки сохраняются после перезапуска. Сервер слушает `127.0.0.1`; остановка — Ctrl+C.

Другой порт и файл БД:

```sh
java -jar target/url-shortener-0.1.0-standalone.jar 9090 links.db
java -jar target/url-shortener-0.1.0-standalone.jar client http://localhost:9090
```

## Меню клиента

1. **Создать** — введите обычный URL, например `https://example.com/articles?id=12`. Ответ — короткий идентификатор, например `9e54a10fbc`.
2. **Показать** — введите идентификатор. Ответ — сохранённый обычный URL.
3. **Изменить** — введите через пробел идентификатор и новый URL: `9e54a10fbc https://example.org/new`.
4. **Удалить** — введите идентификатор. Ответ — `OK`.
5. **Выйти** — завершить клиент.

Можно вводить номер или название действия. Ответ выводится в формате `Ответ: ...`. При отсутствии ссылки, неверном URL или недоступном сервере — `Ответ: Ошибка`. Конец ввода также завершает клиент.

Поддерживаются абсолютные HTTP/HTTPS URL с именем хоста. Короткий URL в рамках задания — идентификатор, используемый командой «Показать»; HTTP GET возвращает текст исходного адреса.

## HTTP API

| Метод | Путь | Успешный ответ |
|---|---|---|
| POST | `/{normal-url}` | 201, короткий идентификатор |
| GET | `/{short-url}` | 200, исходный URL |
| PUT | `/{short-url}/{normal-url}` | 200, `OK` |
| DELETE | `/{short-url}` | 200, `OK` |

Каждый параметр пути кодируется в UTF-8 через URL encoding. Это сохраняет `?`, `#`, `&`, `%`, `+` и слеши внутри исходного URL. Клиент делает кодирование автоматически. Тело ответа — `text/plain; charset=utf-8`.

Ошибки: 400 — некорректный URL/формат, 404 — ссылка не найдена, 405 — неподдерживаемый метод, 500 — внутренняя ошибка. Тело ошибки — `Ошибка`.

## Сборка из исходников

Установите JDK 17+ и Leiningen. Для загрузки зависимостей нужен интернет.

Linux/macOS:

```sh
chmod +x build.sh
./build.sh
```

Windows:

```bat
build.bat
```

Или вручную:

```sh
lein deps
lein test
lein uberjar
```

## Структура

- `project.clj` — зависимости, точка входа и имя JAR.
- `src/url_shortener/core.clj` — выбор режима клиента или сервера.
- `src/url_shortener/db.clj` — SQLite и параметризованные SQL-запросы.
- `src/url_shortener/server.clj` — HTTP API на встроенном сервере JDK.
- `src/url_shortener/client.clj` — HTTP-клиент JDK и меню терминала.
- `test/url_shortener/core_test.clj` — интеграционные проверки API и сохранения данных.
- `target/url-shortener-0.1.0-standalone.jar` — готовая программа.

Короткий идентификатор генерируется из UUID. Уникальность гарантирует первичный ключ SQLite: при коллизии генерация повторяется. Все значения передаются в SQL как параметры.

## Проверки

Интеграционный тест запускает настоящий HTTP-сервер и проверяет создание, получение, изменение, удаление, ошибки, передачу специальных символов и открытие той же БД вторым сервером.
